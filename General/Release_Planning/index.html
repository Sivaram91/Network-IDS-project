    NETWORK INTRUSION DETECTION SYSTEM WITH TINYML¶

    RELEASE PLAN¶

    Project: Network IDS with TinyML Author: Sivaramasubramanian Sundararaj Document Version: 1.0

    Last updated: 12-Feb-2026

    RELEASE OVERVIEW¶

    Total Releases: 5 (4 core phases + 1 RAG enhancement) Timeline: February 2025 - February 2026 (13 months) Total Features: 12 Total Story Points Estimate: 450 hours

    Release Schedule:¶

    • Release 1 (Phase 1): February - May 2025 (4 months)
    • Release 2 (Phase 2): June 2025 (1 month)
    • Release 3 (Phase 3): July - August 2025 (2 months)
    • Release 4 (Phase 4): September - November 2025 (3 months)
    • Release 5 (RAG): December 2025 - February 2026 (3 months)

    RELEASE 1: CORE FUNCTIONALITY (PHASE 1)¶

    Release Date: May 31, 2025 Duration: 4 months (February - May 2025) Effort: 150 hours Goal: Portfolio-ready working intrusion detection system

    Features Included:¶
    • FEAT-001: Network Traffic Capture
    • FEAT-002: ML-based Intrusion Detection
    • FEAT-003: TinyML Fuzzing Detection
    • FEAT-004: Attack Simulation
    • FEAT-005: System Integration
    Success Criteria:¶

    [x] Raspberry Pi captures and analyzes network traffic [x] ML model detects 3+ attack types with >90% accuracy [x] STM32 detects fuzzing attacks using TinyML [x] System demonstrates end-to-end detection capability [x] Complete documentation available [x] Demo video created

    EPIC 1.1: NETWORK TRAFFIC CAPTURE (FEAT-001)¶

    Epic Owner: Sivaramasubramanian Sundararaj Priority: Critical Effort Estimate: 30 hours Dependencies: Hardware setup complete

    User Story: As a security analyst, I want to capture network traffic in real-time so that I can analyze it for potential threats.

    Acceptance Criteria: - System captures minimum 100 packets per second - All packet metadata extracted correctly - PCAP files generated for offline analysis - System handles storage limitations gracefully

    Stories (Tasks):

    STORY 1.1.1: Hardware Setup¶

    Description: Setup Raspberry Pi 4 with required OS and network configuration Effort: 4 hours Tasks: - Flash Raspberry Pi OS to SD card - Configure SSH access - Setup static IP addressing - Install system updates - Configure Ethernet interface Acceptance: Pi boots successfully and accessible via SSH

    STORY 1.1.2: Python Environment Setup¶

    Description: Install and configure Python packages for packet capture Effort: 3 hours Tasks: - Install Python 3.9+ - Install Scapy library - Install pandas, numpy - Verify packet capture permissions - Test basic Scapy functionality Acceptance: All imports successful, test capture works

    STORY 1.1.3: Packet Capture Module¶

    Description: Implement real-time packet capture functionality Effort: 8 hours Tasks: - Create PacketCapture class - Implement sniff callback function - Add packet parsing logic - Extract IP, port, protocol, flags - Implement packet buffering - Add error handling Acceptance: Captures 100+ pps with all fields extracted

    STORY 1.1.4: PCAP File Writer¶

    Description: Save captured packets to PCAP format Effort: 4 hours Tasks: - Implement PCAP writer using Scapy - Add file rotation mechanism - Implement file naming convention (timestamp-based) - Add metadata headers Acceptance: Generated PCAP opens in Wireshark correctly

    STORY 1.1.5: Storage Management¶

    Description: Implement circular buffer for storage management Effort: 6 hours Tasks: - Monitor disk space usage - Implement circular buffer mechanism - Delete oldest files when >80% full - Add logging for storage events - Test with limited storage Acceptance: System runs 24h without storage failure

    STORY 1.1.6: Unit Tests¶

    Description: Create unit tests for capture module Effort: 5 hours Tasks: - Test packet parsing accuracy - Test PCAP file generation - Test storage management - Test error handling - Achieve 80% code coverage Acceptance: All tests pass, coverage >80%

    EPIC 1.2: ML-BASED INTRUSION DETECTION (FEAT-002)¶

    Epic Owner: Sivaramasubramanian Sundararaj Priority: Critical Effort Estimate: 40 hours Dependencies: EPIC 1.1 complete

    User Story: As a network administrator, I want the system to automatically detect network attacks using machine learning so that I can respond to threats quickly.

    Acceptance Criteria: - Detects port scanning with >90% accuracy - Detects DoS attacks with >90% accuracy - Detects data exfiltration with >85% accuracy - False positive rate <5% - Real-time alerts generated within 100ms

    Stories (Tasks):

    STORY 1.2.1: Feature Engineering Design¶

    Description: Design and document feature extraction strategy Effort: 5 hours Tasks: - Research network flow features - Define feature list (packet count, byte count, timing, etc.) - Design time window mechanism - Document feature rationale Acceptance: Feature specification document complete

    STORY 1.2.2: Feature Extraction Module¶

    Description: Implement feature extraction from packet data Effort: 10 hours Tasks: - Create FeatureExtractor class - Implement flow aggregation (5-tuple) - Calculate statistical features (mean, std, entropy) - Implement time windowing (configurable) - Extract protocol-specific features (TCP flags) - Validate feature correctness Acceptance: All features extracted correctly for test flows

    STORY 1.2.3: Training Data Collection¶

    Description: Collect and label training dataset Effort: 6 hours Tasks: - Capture normal traffic (home network) - Generate attack traffic (port scan, DoS, exfiltration) - Label dataset (normal vs attack type) - Split into train/validation/test sets - Save dataset to CSV Acceptance: Labeled dataset with 1000+ samples per class

    STORY 1.2.4: ML Model Training¶

    Description: Train machine learning models Effort: 8 hours Tasks: - Implement Random Forest classifier - Implement Isolation Forest (anomaly detection) - Feature scaling/normalization - Hyperparameter tuning - Cross-validation - Model evaluation (accuracy, precision, recall) Acceptance: Models achieve >90% accuracy on validation set

    STORY 1.2.5: Real-time Detection Engine¶

    Description: Implement real-time detection using trained models Effort: 8 hours Tasks: - Create DetectionEngine class - Load trained models - Implement sliding window processing - Generate alerts on detection - Measure latency (target <100ms) - Add logging Acceptance: Real-time detection working with <100ms latency

    STORY 1.2.6: Model Persistence¶

    Description: Save and load trained models Effort: 3 hours Tasks: - Implement model serialization (joblib) - Version control for models - Load model at startup - Handle model loading errors Acceptance: Models persist across restarts

    EPIC 1.3: TINYML FUZZING DETECTION (FEAT-003)¶

    Epic Owner: Sivaramasubramanian Sundararaj Priority: Critical Effort Estimate: 40 hours Dependencies: STM32 hardware available

    User Story: As an embedded systems engineer, I want to detect malformed packets on the STM32 gateway using TinyML so that I can provide edge-level security.

    Acceptance Criteria: - TinyML model <100KB - Inference latency <10ms per packet - RAM usage <50KB - Detection accuracy >85% for fuzzing attacks

    Stories (Tasks):

    STORY 1.3.1: STM32 Development Environment¶

    Description: Setup STM32 development tools and test basic functionality Effort: 6 hours Tasks: - Install STM32CubeIDE - Install ST-Link drivers - Create new project for NUCLEO-H755ZI - Configure clock settings - Test GPIO (LED blink) - Test UART debug output Acceptance: LED blinks, debug messages visible

    STORY 1.3.2: Ethernet Driver Setup¶

    Description: Configure Ethernet peripheral on STM32 Effort: 8 hours Tasks: - Configure Ethernet peripheral in CubeMX - Initialize Ethernet MAC and PHY - Implement basic packet reception - Setup static IP (192.168.10.2) - Test ping from Raspberry Pi - Debug Ethernet issues Acceptance: STM32 responds to ping from Pi

    STORY 1.3.3: TensorFlow Lite Micro Integration¶

    Description: Integrate TFLite Micro into STM32 project Effort: 8 hours Tasks: - Download TFLite Micro library - Add to STM32 project - Configure build settings - Test with example model - Verify compilation - Measure memory footprint Acceptance: Example TFLite model runs on STM32

    STORY 1.3.4: Fuzzing Detection Model Training¶

    Description: Train lightweight model for fuzzing detection Effort: 6 hours Tasks: - Generate fuzzing attack dataset (malformed packets) - Design lightweight model architecture - Train on laptop (Keras) - Quantize to int8 - Convert to TFLite format - Verify model size <100KB Acceptance: Quantized TFLite model <100KB, accuracy >85%

    STORY 1.3.5: On-Device Inference¶

    Description: Implement inference on STM32 Effort: 8 hours Tasks: - Load TFLite model to STM32 flash - Extract features from incoming packets - Run inference using TFLite interpreter - Measure inference latency - Optimize for <10ms latency - Measure RAM usage Acceptance: Inference <10ms, RAM <50KB

    STORY 1.3.6: Testing and Validation¶

    Description: Test TinyML detection on real traffic Effort: 4 hours Tasks: - Send normal packets from Pi - Send fuzzing attacks from Pi - Verify detection accuracy - Test edge cases - Performance benchmarking Acceptance: >85% accuracy on test set

    EPIC 1.4: ATTACK SIMULATION (FEAT-004)¶

    Epic Owner: Sivaramasubramanian Sundararaj Priority: High Effort Estimate: 20 hours Dependencies: Network setup complete

    User Story: As a tester, I want to generate various network attacks so that I can validate the detection capabilities of the system.

    Acceptance Criteria: - Port scan simulation (configurable rate) - DoS attack simulation (high packet rate) - Fuzzing attack simulation (malformed packets) - Data exfiltration simulation - All attacks logged with parameters

    Stories (Tasks):

    STORY 1.4.1: Attack Simulator Framework¶

    Description: Create framework for attack simulation Effort: 4 hours Tasks: - Create AttackSimulator class - Define attack interface - Implement logging mechanism - Add configuration parser Acceptance: Framework structure complete

    STORY 1.4.2: Port Scan Simulator¶

    Description: Implement port scanning attack generator Effort: 4 hours Tasks: - Implement SYN scan (TCP) - Make port range configurable - Make scan rate configurable (1-1000 ports/sec) - Log scan parameters - Verify with Wireshark Acceptance: Port scan detectable by IDS

    STORY 1.4.3: DoS Attack Simulator¶

    Description: Generate DoS attack traffic Effort: 4 hours Tasks: - Implement high-rate packet generation - Target configurable IP/port - Configurable packet rate (up to 1000 pps) - Multiple source IPs (spoofing) - Log attack parameters Acceptance: DoS attack detectable by IDS

    STORY 1.4.4: Fuzzing Attack Simulator¶

    Description: Generate malformed packets for fuzzing Effort: 4 hours Tasks: - Generate packets with invalid length - Corrupt packet headers - Invalid checksums - Random payload data - Log fuzzing parameters Acceptance: Fuzzing detectable by STM32 TinyML

    STORY 1.4.5: Data Exfiltration Simulator¶

    Description: Simulate data exfiltration pattern Effort: 4 hours Tasks: - Generate sustained upload traffic - Large packet sizes (near MTU) - Configurable target IP - Realistic timing patterns - Log exfiltration parameters Acceptance: Exfiltration detectable by ML model
